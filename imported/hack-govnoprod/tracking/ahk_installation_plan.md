# План доставки и автоматической установки AutoHotkey и `.ahk`-скрипта

Ниже — детализированный план реализации полностью автоматических шагов 1–7 и UI c фолбэками (п. 8–10, 12), включая обработку AV/SmartScreen и четкие критерии приемки.

Общие требования
- Автоматизировать пункты 1–7 без ручных действий пользователя (кроме согласия).
- Предусмотреть UI для ручной установки и инструкций (п. 8–9).
- Если антивирус/SmartScreen блокирует — предложить ручную установку с инструкциями и ссылками.
- Учитывать работу без прав администратора; elevation запрашивать только когда реально нужен.

1. Подготовка артефактов
   - Задачи:
     - Хранить артефакты в `./assets/bin/ahk/`:
       - Вариант A (предпочтительно): портативный `AutoHotkey.exe` (v2, x64) + необходимые DLL.
       - Вариант B (фолбэк): официальный инсталлятор `AutoHotkey_*.exe`.
     - Добавить `hashes.json` с SHA256:
       ```json
       {
         "portable/AutoHotkey64.exe": "<SHA256>",
         "installer/AutoHotkey_v2.exe": "<SHA256>"
       }
       ```
     - Создать шаблон `script.ahk.tpl` с плейсхолдерами:
       - `{AUTOHOTKEY_PATH}`, `{SCRIPT_DIR}`, `{LOG_DIR}`, `{PREPROMPT}`, `{HOOKS}`, `{PORT}` и т.п.
     - Обозначить минимальные версии: `Requires AutoHotkey v2`.
   - Критерии приемки:
     - Файлы лежат в `./assets/bin/ahk/` и перечислены в `hashes.json`.
     - Контент `script.ahk.tpl` валиден и покрывает требуемые настройки.

2. Автоматический запрос согласия и UI-флоу
   - Задачи:
     - При `activate()` отображать модальный диалог (один раз) с текстом:
       - Что будет установлено (AHK), где будут храниться файлы (`globalStoragePath`), зачем (горячие клавиши/захват пресендов).
     - Кнопки: `Установить автоматически`, `Только .ahk (ручная установка)`, `Отмена`, ссылка `Подробнее` (инфо-страница).
     - Сохранять решение в `globalState` (флаг подавления повторных показов + timestamp/версия согласия).
   - Критерии приемки:
     - Диалог показывается однократно до изменения версии/настроек.
     - Выбор пользователя влияет на дальнейший поток без дополнительной рутины.

3. Копирование и проверка целостности
   - Задачи:
     - По согласию — копировать бинарники в `context.globalStoragePath/bin/`.
     - Вычислять и сверять SHA256 (Node `crypto.createHash('sha256')`).
     - При несовпадении checksum — удалять файл и переходить к ручной установке (UI из п.8).
   - Критерии приемки:
     - В журнале фиксируется «копирование успешно» и «SHA256 ок». При ошибке — понятное сообщение и фолбэк.

4. Детект установленного AHK
   - Задачи:
     - Проверять:
       - `where autohotkey` (через `cmd /c where AutoHotkey.exe`).
       - Типовые пути: `C:\Program Files\AutoHotkey\v2\AutoHotkey.exe`, `C:\Program Files\AutoHotkey\AutoHotkey.exe`.
       - WMI/CIM: `Get-CimInstance Win32_Process` для текущих процессов (на случай уже запущенного AHK).
     - Если найден системный AHK v2 — предложить использовать его.
   - Критерии приемки:
     - Корректно определяется наличие/отсутствие AHK v2; путь сохранен в настройках.

5. Установка/распаковка с правами по необходимости
   - Задачи:
     - Если выбран инсталлятор, запускать PowerShell с elevation (если нужен):
       - NSIS (предположение): аргументы `/S`.
       - Inno Setup (предположение): `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /DIR="C:\\Program Files\\AutoHotkey"`.
       - Команда:
         ```powershell
         Start-Process -FilePath "<installer>" -ArgumentList "/S" -Verb RunAs -Wait -WindowStyle Hidden
         ```
       - Если неизвестен тип инсталлятора — предлагать портативный вариант.
     - Для портативной версии — просто копировать `AutoHotkey.exe` в `globalStoragePath/bin/`.
     - Читать exit code, писать лог.
   - Критерии приемки:
     - При успехе — exit code 0, `AutoHotkey.exe` доступен, путь сохранён.
     - При неуспехе — UI фолбэк на ручную установку.

6. Генерация `.ahk` из шаблона
   - Задачи:
     - Формировать карту подстановок:
       - `{AUTOHOTKEY_PATH}` → выбранный путь к `AutoHotkey.exe`.
       - `{SCRIPT_DIR}` → `globalStoragePath/scripts` (создать при необходимости).
       - `{LOG_DIR}` → `globalStoragePath/logs`.
       - `{PREPROMPT}` → строка/многострочник из настроек.
       - `{HOOKS}` → JSON со списком хоткеев.
     - Сохранять `script.ahk` (CRLF), проверять наличие директив `#Requires AutoHotkey v2`, `#SingleInstance Force`.
   - Критерии приемки:
     - Файл записан, плейсхолдеры подставлены, базовая валидация пройдена.

7. Автоматический запуск/перезапуск скрипта
   - Задачи:
     - Остановить предыдущий экземпляр (если надо):
       - Через `taskkill /F /IM AutoHotkey.exe /FI "WINDOWTITLE eq <custom-title>"` или
       - Полагаться на `#SingleInstance Force` в самом скрипте.
     - Запускать невидимо:
       ```powershell
       Start-Process -FilePath "<AutoHotkey.exe>" -ArgumentList "`"<script.ahk>`"" -WindowStyle Hidden
       ```
     - Альтернатива (Node): `spawn(ahkPath, [scriptPath], { detached: true, stdio: 'ignore' })`.
     - Health-check: убедиться, что процесс запущен и держится >2 сек.
   - Критерии приемки:
     - Процесс есть, скрипт активен (хоткей работает), ошибок в логах нет.

8. UI: ручная установка и управление
   - Задачи:
     - Панель `InstallPanel` (`src/ui/installPanel.tsx`):
       - Кнопки: `Скачать официальный AHK`, `Сохранить .ahk`, `Открыть папку скриптов`, `Повторить автоустановку`.
       - Пошаговые инструкции с код-блоками PowerShell.
     - Показывать путь к логам и бинарникам.
   - Критерии приемки:
     - Все кнопки работают; инструкции читабельны; ссылки открываются в браузере.

9. Инструкции по AV/SmartScreen + ссылки
   - Задачи:
     - Добавить раздел с инструкциями:
       - SmartScreen: «Дополнительные сведения» → «Выполнить в любом случае».
       - Свойства файла → `Разблокировать`.
       - Для Defender: исключение на папку `globalStoragePath/bin/` (по желанию).
     - Ссылки:
       - AutoHotkey (официальный сайт): [autohotkey.com](https://www.autohotkey.com/)
       - Документация SmartScreen: [support.microsoft.com](https://support.microsoft.com/)
     - Если блокируется — показывать ветку UI для ручной установки.
   - Критерии приемки:
     - Раздел доступен из основного UI, ссылки корректны, текст ясен.

10. Очистка при деактивации/удалении
    - Задачи:
      - Предлагать пользователю очистку при деактивации: удалить `bin/`, `scripts/`, `logs/` в `globalStoragePath`.
      - Остановить запущенные AHK-скрипты, удалить ярлыки/временные файлы.
    - Критерии приемки:
      - После подтверждения всё удалено; процессы завершены.

11. Альтернативные фолбэки (без дистрибуции `.exe`)
    - Задачи:
      - Генерировать только `.ahk` и открывать UI с шагами ручной установки AHK.
      - (Опционально) описать локальный агент/вебхук как альтернативу.
    - Критерии приемки:
      - Пользователь может завершить настройку без поставки `.exe`.

12. Приватность и безопасность
    - Задачи:
      - Не отправлять внешние запросы без согласия.
      - Не хранить токены в открытом виде; SecretStorage при необходимости.
      - Проверять SHA256 каждой копии; логировать несоответствия.
      - (Опционально) Проверять наличие цифровой подписи файла и отображать статус в UI.
    - Критерии приемки:
      - Все проверки выполняются; приватные данные не утекли.

13. Логи и диагностика
    - Задачи:
      - Писать текстовые логи в `globalStoragePath/logs/ahk-installer-<date>.log`.
      - Логировать: время, действие, путь, exit code, hash-ok, ошибки.
      - Кнопка «Показать лог» в UI.
    - Критерии приемки:
      - Логи доступны, полнота достаточна для отладки.

Разворачиваемая структура файлов
- `extensions/apps/vscode-ext/assets/bin/ahk/portable/AutoHotkey64.exe`
- `extensions/apps/vscode-ext/assets/bin/ahk/installer/AutoHotkey_v2.exe`
- `extensions/apps/vscode-ext/assets/bin/ahk/hashes.json`
- `extensions/apps/vscode-ext/assets/bin/ahk/script.ahk.tpl`
- `extensions/apps/vscode-ext/src/install/installer.ts`
- `extensions/apps/vscode-ext/src/ui/installPanel.tsx`
- Runtime: `globalStoragePath/bin/*`, `globalStoragePath/scripts/*`, `globalStoragePath/logs/*`

Примечания и предположения
- Флаги установщиков указаны как предположение (NSIS `/S`, Inno `/VERYSILENT ...`). Если тип иной — использовать портативный вариант.
- Для остановки предыдущих инстансов достаточно `#SingleInstance Force` в `.ahk`, но `taskkill` оставить как резерв.
- Не добавляем автозагрузку в «Пуск/Автозагрузка», только немедленный запуск после установки.

Мини-пример содержимого `script.ahk.tpl`
```ahk
#Requires AutoHotkey v2.0
#SingleInstance Force

; Конфиг подставляется из расширения
global SCRIPT_DIR := "{SCRIPT_DIR}"
global LOG_DIR    := "{LOG_DIR}"
global PREPROMPT  := "{PREPROMPT}"

; Пример хоткея: Ctrl+Alt+C — вставить пресенд
^!c:: {
    SendText(PREPROMPT)
}

SendText(text) {
    A_Clipboard := text
    Sleep 50
    Send "^v"
}
```

Команды PowerShell, которые будут использоваться
```powershell
# Elevation и запуск установщика (пример)
Start-Process -FilePath "<installer>" -ArgumentList "/S" -Verb RunAs -Wait -WindowStyle Hidden

# Запуск портативного AHK со скриптом (скрытно)
Start-Process -FilePath "<AutoHotkey.exe>" -ArgumentList "`"<script.ahk>`"" -WindowStyle Hidden

# Проверка SHA256 (альтернатива внутри расширения)
Get-FileHash -Algorithm SHA256 "<path>\AutoHotkey.exe"
```

Критерии «Готово» для всего эпика
- Пользователь с одним кликом (после согласия) получает работающий AHK-скрипт (п.1–7 автоматом).
- При блокировке AV/SmartScreen доступна полноценная альтернатива с инструкциями и ссылками (п.8–9).
- Чистая деинсталляция по запросу (п.10).
- Документированы приватность и проверка целостности (п.12), предусмотрены логи (п.13).
